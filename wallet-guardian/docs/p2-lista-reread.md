# Lista 原地址單步領取的獨立唯讀重讀

客戶端用固定政策重讀鏈上狀態，核對這筆任務是否仍是同一個帳戶、同一筆提款、同一個部署、同一段 `claimWithdraw(uint256)`。RPC、ABI、proxy 與允許的操作來自這份客戶端政策，對應 `config/chains.json` 與 `config/protocols/lista-bsc.json`。任務 JSON 不能指定這些來源。

重讀在同一個區塊上重建：原地址、以 uuid 對上的目前索引、可領、暫停、實作與程式碼、以及精確的 calldata 與 value。不預先採用計畫裡的舊索引。讀到區塊標頭之後，狀態呼叫使用 EIP-1898 `{blockHash, requireCanonical:true}`。節點若不接受這個參數，結果是資料不足，不會改回只用區塊高度還標成通過。這份紀錄沒有對公開 BSC RPC 做過 EIP-1898 相容性實測。

部署核准是 `config/protocols/lista-bsc.json` 裡的版本化客戶端清單（實作地址、proxy 與實作程式碼雜湊、出處、有效期）。任務 JSON 不能提供這份清單，鏈上讀到的雜湊也不會自動核准。和任務一致但未核准時，觀察可以留下，完整重讀不能通過。目前清單是空的。

完整通過需要計畫帶有尚未到期的整數 `local_ttl_unix`。缺少、null、字串或非法數字只留資料不足。有效時間取最早的一項：該期限、區塊時間加 120 秒、讀取開始加 120 秒，以及這次所用核准的 `validUntil`。沒有明確期限的核准不能當成永久，除非政策自己標成永久。核准在保存期間到期後，已顯示的通過會作廢。

開始下一次重讀時，畫面上的舊通過先標成更新中。到期、分頁重新取得焦點，以及錢包斷線或提供者更換，都會重算或作廢。登出、取消、revision、帳戶與鏈的世代檢查仍然在。這一輪的錢包帳戶與 `eth_chainId` 都要成功，而且鏈要是政策裡的鏈。查詢失敗不會沿用上一輪的鏈，也不會把 RPC 看到的鏈當成錢包的鏈。沒有這兩項時，鏈上觀察可以留下，不能算完整通過。

JSON-RPC 回應最多讀 1 MiB，必須是 UTF-8 的 JSON-RPC 2.0，id 要對上，而且 result 與 error 只能有一個。這只檢查信封，不是鏈上事實。

畫面三項分開：

1. 獨立鏈上重讀：通過 / 失敗 / 資料不足
2. 交易效果模擬：通過 / 失敗 / 未做
3. 允許實際送出：關閉

重讀通過不會寫回 `preflight_ok`，也不會把未完成的模擬標成通過。

鎖畫面不等於鎖鏈。lock screen ≠ lock chain.

## 不做

主網送出、模式 B／C、TUF、Pages 部署、讓確認鈕真正送出。模式 A 的引導路徑與不廣播測試見 `docs/mode-a-lista.md`。重讀通過仍然不是送出授權。
